# Marketplace (Доска объявлений)

Это бэкенд-проект для сайта объявлений, который реализует следующие функции:

- Регистрация, аутентификация пользователей
- Роли пользователей: обычные пользователи и администраторы
- Восстановление пароля через электронную почту
- CRUD операции для объявлений
- Отзывы под объявлениями
- Поиск по объявлениям
- Статическая и динамическая страница

## Стек технологий

- **Python** 3.12
- **Django** 5.1.7
- **Django Rest Framework (DRF)**
- **PostgreSQL** для хранения данных
- **Docker** для контейнеризации
- **NGINX** для обработки статики
- **simple-jwt** для аутентификации через JWT
- **pytest** для тестирования
- **Swagger** для документации API

## Установка и запуск

### 1. Клонируйте репозиторий

```bash
git clone git@github.com:aleksospishev/MarketPlace_Diplom.git
cd marketplace
```
### 2. Создайте файл .env
Скопируйте пример файла окружения:

```bash
cp .env.example .env
```

Отредактируйте .env файл с необходимыми переменными окружения:

```.env
SECRET_KEY = your secret key Django

POSTGRES_DB = your database
POSTGRES_USER = your user database
POSTGRES_PASSWORD = your password database
POSTGRES_HOST = your host database
PORT = your port database

DEBUG = True


E_MAIL = your email
PASS_MAIL= your password email
```

### 3. Запуск с использованием Docker
Чтобы собрать и запустить проект с помощью Docker, используйте команду:

``` bash
docker-compose up --build
```

Это создаст и запустит контейнеры для:
PostgreSQL (db)
Django (web)
NGINX для обслуживания статики

### 4. Cоздание суперпользователя
Чтобы создать суперпользователя (администратора), используйте команду:

```bash
docker-compose exec web python manage.py CSU
```

### 5. Доступ к API
После того как контейнеры запущены, вы можете получить доступ к API на следующем адресе:

Swagger UI: http://localhost/redoc/ – для документации API

Админ-панель Django: http://localhost/admin/ – для работы с админкой


### 6. Остановка контейнеров
Для остановки контейнеров используйте команду:

```bash
docker-compose down
```

## API Endpoints
### 1. Пользователь
POST /users/register/ — Регистрация пользователя

POST /users/login/ — Логин пользователя

POST /users/logout/ — Логаут пользователя

GET /users/profile/ — Просмотр профиля пользователя

PUT /users/profile/ — Обновление профиля пользователя

### 2. Объявления
GET /ads/ — Получить список всех объявлений с пагинацией и фильтрацией

POST /ads/ — Создать новое объявление

GET /ads/{id}/ — Получить подробности конкретного объявления

PATCH /ads/{id}/update/ — Обновить объявление

DELETE /ads/{id}/delete/ — Удалить объявление

### 3. Комментарии
GET /comments/ — Получить список всех комментариев

POST /comments/ — Создать комментарий

PATCH /comments/{id}/update/ — Обновить комментарий

DELETE /comments/{id}/delete/ — Удалить комментарий

## Настройка статики
Для того чтобы правильно обслуживать статические файлы через NGINX, в контейнере nginx настроены следующие директории:

/static — Статические файлы для Django.

## Тестирование
Проект использует pytest для тестирования.
Покрытие тестам составляет 93%.
Чтобы запустить тесты, используйте команду:

```bash
USE_SQLITE_FOR_TESTS=1 pytest
```

## Примечания
Проект использует JWT для аутентификации. После успешной авторизации пользователю возвращается токен, который нужно использовать для доступа к защищённым эндпоинтам.

Для удобства работы с API используется Swagger (Redoc) для автогенерации документации.

Для хранения данных используется база данных PostgreSQL.

Статика (CSS, JS, изображения) обслуживается через NGINX.
